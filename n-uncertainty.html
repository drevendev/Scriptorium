Что скрывает N?

В закреплённом AOT/pylem 0.0.18 обозначение N может относиться и к существительному, и к количественному числительному. Мы измерили масштаб этой неопределённости на полной зафиксированной русской редакции «Анны Карениной», не угадывая правильный разбор каждого слова.

Где теряется определённость

Из 269 358 токенов у 117 554 есть консервативно определённая категория; ещё 55 081 содержат только N. В гипотезе, где все такие N отнесены к существительным или числительным, определёнными стали бы 172 635 токенов. Это не подтверждённая морфология FantLab.

Полоса показывает долю N-only от всех токенов, а не доверительный интервал. Минимум и максимум для каждого POS-бакета — 0…55 081; оба максимума одновременно невозможны.

Два возможных чтения N

В условном подмножестве из 172 635 определённых токенов верхняя граница для каждой из двух категорий — 31,906045%. Это доля условно определённых токенов, не доля существительных или числительных во всём тексте.

Влияние на биграммы

Границы вычислены для каждой пары отдельно динамическим программированием с единственным назначением N для каждого токена. Достижимый максимум учитывает ограничения соседних токенов; независимый верхний предел складывает возможные рёбра и может завышать результат. Ни один набор максимумов не является общей разметкой.

Позиция в предложении

Для первых пяти позиций верхняя граница одинакова для каждой из двух конкурирующих категорий, но не может достигаться для обеих одновременно. Знаменатель — все 21 228 предложений, не число N-only токенов.

Проверка нативными примерами

На закреплённом pylem проверены три лексических набора по три слова. Названия групп — человеческая аннотация примеров, а не восстановленная часть речи из AOT. Доля N-only вычислена только внутри каждой группы: это не точность классификатора и не частота по всей книге.

Как повторить и проверить

Измерение произведено исходным закреплённым Python 3.9 / AOT-пакетом pylem==0.0.18, а расчёт границ — версионированным кодом Scriptorium. GitHub Actions сохранил исходный source-free JSON; контрольные суммы связывают его с точным входом и нативным результатом.
